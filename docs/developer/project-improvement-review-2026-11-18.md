# Where ELTS can improve

**Working-tree review · November 18, 2026**

The original rehearsal reproduced an intake error where typing `12x` selected participant `12`. The findings and baseline measurements below describe the checkout **before implementation**. The dashboard now offers a picker of saved numeric IDs, and the calibration workspace has a numeric picker for creating IDs. A session can be aborted by confirming once. Operators can no longer enter session notes.

The software changes also cover session-plan editing, captions, the optional display check, offline station migration, recovery exports, scoped workbooks, and on-demand preview. On this Windows machine, three repeat refreshes of 100 unchanged fictional recording folders took **11–14 ms** with zero recordings reparsed. An isolated 3,500-sample analysis produced the same report while reducing peak Python allocation from **6.12 to 1.86 MiB**. The original benchmark and its scope are documented below.

Three further software checks measured the effect of caching. On this machine an unchanged scan of 300 fictional profiles took a median **1.37 ms**, compared with **99.6 ms** to validate them with a fresh inventory. A 30-poll, 1,000-attempt HTTP benchmark transferred **2.0 MB** with revision-based review loading, compared with **30.3 MB** when the same review was included on each poll. The source-fingerprint check took **109–260 ms** in three consecutive runs with an empty station. With the toolchain already installed and package dependencies cached, a clean test checkout took **192.2 s** to build and reach dashboard readiness. Two launches that verified and reused that build took **9.0 s** each, including about 0.36 s to verify the saved player. Per-stage times are available under `diagnostics/start-summary.json`.

The packaged Windows rehearsal was built with Unity 6000.3.23f1. Its Unity project passed 38 Play Mode tests and 3 Edit Mode tests. A real copied player exercised duplicate intake, recordings, abort without a note, failed indexing, an interrupted recording, recovery export, confirmed permanent removal and an empty restart on fictional data. The dashboard, shared ID and reason fixtures, station copy/restore, and raw-recording checks are exercised separately.

For the current workflow, use the [operator guide](../operator/user-guide.md), [portable rehearsal instructions](development-package.md), and [data collection reference](modules/data-collection.md). Observing first-time operators, assessing participant comprehension and room-distance readability, validating device-clock alignment, and obtaining investigator approval still require the people and equipment involved.

The recommendations below cover the operator, participant, analyst, and maintainer. **Small** means a localized change and regression check. **Medium** crosses a workflow or component boundary. **Large** involves deployment, migration, or coordination across teams. These are relative estimates. Items described as trials need observation before committing to implementation.

## 1. Correct decisions the interface can get wrong

1. **Reject ambiguous participant IDs before lookup. Small, first.** Preserve the value that was entered and display the offending format. Keep the agreed handling of leading zeroes explicit. Only enable creation for an exact valid match. Test `0`, a known ID, an unknown ID, `12x`, pasted punctuation, and an overlong paste. Run the same cases in the profile editor so the two surfaces agree. [Dashboard intake](../../unity/Assets/StreamingAssets/administrator/app.js) · [Calibration profile editor](../../Calibration%20Environment/web/app.js)
2. **Tell the truth when a preset cannot be saved. Small.** With browser storage blocked, Settings simultaneously displayed “Saved setup” and a storage error. Return a success result from persistence, retain the draft on failure, and place one outcome beside **Save setup**. Verify a reported success survives reopening the browser. [Preset save handler](../../unity/Assets/StreamingAssets/administrator/workflows.js)
3. **Fix the preview-rate selector and test the round trip. Small.** Selecting “20 fps” sent `fps: 4.8`. Bind every option to its stated value, and display the rate the server accepted after a reload. Check 5, 10, 20, and 30. This is a control defect regardless of the computer’s achievable frame rate. [Settings options](../../unity/Assets/StreamingAssets/administrator/index.html) · [Station command handler](../../unity/Assets/ELTS/Operator/DevelopmentTestStation.cs)
4. **Make the limits on notes and reasons match the recorder. Small.** The notes and exception fields accept 2,000 characters. A logged string permits 256. Show the remaining count, keep the draft if saving fails, and check 256 and 257 through the real command path. This matters when an operator is documenting an interruption during a visit. [Dashboard fields](../../unity/Assets/StreamingAssets/administrator/index.html) · [Session event creation](../../unity/Assets/ELTS/Session/SessionRuntime.cs) · [Logging contract](../../unity/Assets/ELTS/Logging/LoggingContracts.cs)
5. **Distinguish a missing profile from an unreadable one. Small to medium.** Both profile inventories skip invalid files. The operator can consequently be told to create a calibration that already exists on disk. For the requested ID, distinguish absent, invalid, unavailable directory, and ready. Give the operator the relevant recovery action and preserve the original file. Exercise all four cases with fixtures. ## Suggested implementation order

1. **First patch.** Fix ID entry, preset feedback, preview-value mapping, note limits, and dialog focus. Add focused regressions for the observed behaviors. Correct the removal wording immediately while the research team decides where names should live.
2. **First end-to-end milestone.** Prove an extracted development package can create, close, verify, export, and reopen a fictional visit outside the repository. Use this journey to identify the smallest package and data-location changes required.
3. **First performance milestone.** Establish the full-station baseline and implement incremental collection indexing with a versioned migration. Compare unchanged refresh work, live responsiveness, and identical derived results. Then decide whether to split the dashboard payload or reduce preview work first.
4. **First operator and analyst milestone.** Use observed rehearsals to pick the dashboard layout, recovery flow, and export improvements. Establish durable storage, tested restore, and recoverable configuration revisions before relying on upgrades for a retained collection.

The isolated session engine, single raw recording writer, checksummed closure, and rebuildable SQLite index are worth preserving. They let the team change operator and analyst workflows and still compare outcomes against the same original evidence. [Architecture](architecture.md) · [Logging design](modules/logging.md)
